Simulation Platform

A pluggable platform that hosts any number of independent process simulations and exposes every running session through a single OPC UA endpoint. CODESYS, SCADA, or any standard OPC UA client browses one server and sees each session as its own folder — stable, named, and unaffected by restarts. The platform now also ships a full browser UI: create, view, and stop sessions without touching a terminal.

Try it now

Fresh Ubuntu 22.04 server, five minutes — then open the browser UI

On the server

$ git clone <repo> cip-sim && cd cip-sim
$ python3.11 -m venv .venv
$ source .venv/bin/activate
$ pip install -r requirements.txt
$ cp .env.example .env
$ nano .env                # set SERVER_IP, GATEWAY_PUBLIC_HOST
$ python manage.py makemigrations sessions_mgr  # see Known Issues
$ python manage.py migrate
$ python manage.py sync_catalog
$ ./scripts/stack.sh up --slug cip_live

Then open http://<server>:8000/ in a browser. The dashboard lists every active session, links to each worker's live page through /s/<slug>/, and lets you stop a session with one click. The makemigrations line is a workaround until P2 commits the missing migration files.

In CODESYS

  1. Add an OPC UA Data Source: opc.tcp://<server>:8080/gateway/
  2. Browse Objects → Gateway → Sessions → cip_live
  3. Read Measurements.LevelPercent — should be 0.0
  4. Write Commands.WaterValveCmd = 1
  5. Watch LevelPercent climb towards 40

The Data Sources tree survives session restarts because the slug stays the same. No more re-browsing after every stack.sh reset. Reusing a slug while the gateway is running currently requires a gateway restart — see Known Issues.

Feature Explainer

Session slugs — stable OPC UA paths

Why a session identifier matters more than it sounds like it should.

Every session is exposed in the OPC UA tree as a folder under Objects/Gateway/Sessions/. The folder name is what CODESYS Data Sources bake into generated struct field names — it becomes part of every Datasource.Gateway.Sessions.<name>.* reference in your PLC project.

Before slugs — UUID folder

A fresh UUID every session:

9043f2a2-db79-4ba4-8f4c-25bd9548f4d5

CODESYS sanitises it into a legal IEC identifier, mangling the name:

_db79_4ba4_8f4c_25bd9548f4d5

Every restart invalidates the entire Data Sources tree. Rows are unwieldy to browse.

After slugs — human-readable

Create with a slug:

./scripts/stack.sh create --slug cip_live

The OPC UA folder becomes:

cip_live

CODESYS sees exactly what you typed. No sanitisation, no invalidation on restart.

How it works

The slug field on the Session model replaces the UUID in the OPC UA tree when set. Behind the scenes, session_id (the UUID) still keys everything that needs identity — Redis heartbeats, port leases, DB lookups, event routing. The slug is purely a display name for the tree. This split means a slug can be reused: creating a session with the same slug stops the prior one and takes over the name. From the PLC's perspective, nothing changed. (Reusing a slug while the gateway is running is currently broken — see Known Issues — and will be fixed in P3.)

The core contract

Every running simulation is exposed as a subtree under Objects/Gateway/Sessions/<session_name>/ on a single gateway endpoint. CODESYS sees one OPC UA server with N folders, each self-describing its schema. Adding a plugin requires no client-side or server-side reconfiguration.

Known Issues 4

Real bugs that surfaced during Packet 1 testing. They are intentionally not fixed as part of P1 (out of scope) and are documented here so nobody trips over them during demos and assumes they are expected behavior. Each is assigned to the packet that should fix it.

Bug

Slug reuse fails without a gateway restart → P3

WorkerMirror.disconnect() does not remove the session folder from the OPC UA tree, so the next session with the same slug fails with BadNodeIdExists. The UI exposes this exact path (Stop a session, then create a new one with the same slug), so it should be fixed before student use.

Suggested fix: delete the session folder node in disconnect().

Bug

Gateway crashes at startup when any session is running → P3

reconcile_existing() does not supply http_port, which is now a required field on SessionReadyEvent. A gateway started while sessions are live raises and exits, so a restart mid-run takes down the whole OPC UA endpoint.

Suggested fix: read http_port from the heartbeat payload, or make the field optional on SessionReadyEvent.

Bug

sessions_mgr migrations are missing from the repo → P2

The control_plane/apps/sessions_mgr/migrations/ directory is not committed, so manage.py migrate on a fresh machine does not create the sessions, simulation_catalog, or session_events tables. Every fresh-server install is blocked until these are generated and committed.

Suggested fix: run python manage.py makemigrations sessions_mgr on a working dev machine and commit the result.

Note

shared/logging.py LoggerAdapter drops per-call extra fields on Python < 3.13 → P3

On Python < 3.13, LoggerAdapter.process() replaces kwargs["extra"] with the adapter's own dict instead of merging, so log.info("...", extra={"session_id": ...}) silently loses the per-call field. Any structured log that relies on per-call extras is affected. This was fixed upstream in Python 3.13 but the project supports 3.11.

Suggested fix: subclass LoggerAdapter in shared/logging.py and merge extra in process().
