Simulation Platform

A pluggable platform that hosts any number of independent process simulations and exposes every running session through a single OPC UA endpoint. CODESYS, SCADA, or any standard OPC UA client browses one server and sees each session as its own folder — stable, named, and unaffected by restarts.

Simulation plugin → Worker process → Gateway aggregates → CODESYS browses

How to use this page

The platform already works end-to-end with CODESYS. What's left is four independent work packets — one per person — that turn it into something a student or operator can run without a terminal, install on a fresh server, and trust under load.

Try it now

Fresh Ubuntu 22.04 server, five minutes

On the server

$ git clone <repo> cip-sim && cd cip-sim
$ python3.11 -m venv .venv
$ source .venv/bin/activate
$ pip install -r requirements.txt
$ cp .env.example .env
$ nano .env                # set SERVER_IP, GATEWAY_PUBLIC_HOST
$ python manage.py migrate
$ python manage.py sync_catalog
$ ./scripts/stack.sh up --slug cip_live

The --slug cip_live argument gives the session a stable OPC UA folder name. Re-run with the same slug to restart it without touching the CODESYS project.

In CODESYS

  1. Add an OPC UA Data Source: opc.tcp://<server>:8080/gateway/
  2. Browse Objects → Gateway → Sessions → cip_live
  3. Read Measurements.LevelPercent — should be 0.0
  4. Write Commands.WaterValveCmd = 1
  5. Watch LevelPercent climb towards 40

The Data Sources tree survives session restarts because the slug stays the same. No more re-browsing after every stack.sh reset.

Dashboard scaffold + template infrastructure

Django dashboard app, base template, session list page at /, http_port plumbing from worker → consumer → model. Ready for the proxy view and detail page.

Session identity split

The wire protocol now carries session_id (UUID) and session_name (slug-or-UUID) separately. Events are unambiguous even when a slug is reused. Fixed a class of races in the reclaim flow.

Oct 2026

Session slugs

CODESYS Data Sources bake the OPC UA path into generated struct names, so a fresh UUID invalidates every reference. Slugs replace the UUID in the OPC UA tree with a stable, human-readable identifier. Data Sources survive re-creations.

Oct 2026

CODESYS end-to-end integration verified

A real CODESYS soft PLC browses the gateway, reads measurements, and writes commands that change physics. This was the highest-risk unknown; it's now the strongest part of the platform.

Oct 2026

Redis bridge, port allocator, worker manager — hardened

XAUTOCLAIM for abandoned messages, atomic HSETNX for port leases, Lua-script ownership check on release. Restart-safe by design.

Oct 2026

Runtime, gateway, daemon, control plane — foundations

Plugin contract, OPC UA adapter, aggregation gateway, worker pool daemon, Django control plane with REST API and event consumer.

Feature Explainer

Session slugs — stable OPC UA paths

Why a session identifier matters more than it sounds like it should.

Every session is exposed in the OPC UA tree as a folder under Objects/Gateway/Sessions/. The folder name is what CODESYS Data Sources bake into generated struct field names — it becomes part of every Datasource.Gateway.Sessions.<name>.* reference in your PLC project.

Before slugs — UUID folder

A fresh UUID every session:

9043f2a2-db79-4ba4-8f4c-25bd9548f4d5

CODESYS sanitises it into a legal IEC identifier, mangling the name:

_db79_4ba4_8f4c_25bd9548f4d5

Every restart invalidates the entire Data Sources tree. Rows are unwieldy to browse.

After slugs — human-readable

Create with a slug:

./scripts/stack.sh create --slug cip_live

The OPC UA folder becomes:

cip_live

How it works

The slug field on the Session model replaces the UUID in the OPC UA tree when set. Behind the scenes, session_id (the UUID) still keys everything that needs identity — Redis heartbeats, port leases, DB lookups, event routing. The slug is purely a display name for the tree. This split means a slug can be reused: creating a session with the same slug stops the prior one and takes over the name. From the PLC's perspective, nothing changed.

Architecture

Server → OPC UA → CODESYS

The whole system exists to serve one thing: a stable OPC UA address space that industrial clients can browse. Everything below the client layer is plumbing that keeps that address space correct and available.

The core contract

Every running simulation is exposed as a subtree under Objects/Gateway/Sessions/<session_name>/ on a single gateway endpoint. CODESYS sees one OPC UA server with N folders, each self-describing its schema. Adding a plugin requires no client-side or server-side reconfiguration.

Plugin Contract

Pure-Python base class. No I/O, no async, no Django imports — the runtime adapts the plugin; the plugin never knows it exists.

  • BaseSimulation — step / snapshot / write_command
  • CommandSpec, MeasurementSpec, StatusSpec
  • Pulse commands for one-shot signals
Runtime ✓ shipped

OPC UA Adapter

Schema-driven. Reads the plugin's declared schema and builds the OPC UA address space automatically. Validates every write; translates plugin errors into OPC UA status codes.

  • Self-describing metadata properties on the root node
  • PostRead/PostWrite feed idle detection
  • Namespace-qualified browse names
Runtime ✓ shipped

HTTP Dashboard

Background thread serving one HTML page + /api/state. Plugin UI is injected from body.html and ui.js; the shell handles polling, freshness, and staleness.

  • Binds to loopback only
  • Proxied through Django (P1)
Runtime ✓ shipped

Plugin Registry

Convention over configuration. A directory under sim_plugins/ with a simulation.py is the entire installation. Duplicate IDs raise at load time.

Gateway ✓ shipped

Aggregation Server

One stable endpoint. CODESYS sees a single OPC UA server with a folder per live session, regardless of how many workers are running.

  • server.py — aggregate address space
  • mirror.py — one WorkerMirror per session
  • main.py — reconciliation + event loop
Gateway ✓ shipped

Self-describing Discovery

Reads the worker's own metadata properties (SimulationId, NamespaceUri) instead of a hardcoded map. A new plugin appears in the tree with zero gateway changes.
